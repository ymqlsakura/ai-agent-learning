# 素材和 Remotion 流程

## 素材职责

素材按照证明力选择，不按照获取方便选择。

| 来源 | 主要职责 | 不能替代 |
| --- | --- | --- |
| 本人录屏和项目 | 真实过程、真实结果、真实数据 | 无 |
| 网页截图和录屏 | 网站、产品、文章和在线状态 | 操作过程不能只靠一张首页图 |
| 官方和第一方素材 | 功能、命令、界面和事实依据 | 不能伪装成本人实操 |
| Pexels | 通用人物、办公和环境过渡 | 本人结果和产品过程 |
| Codex 生图 | 情绪、隐喻、故事化主视觉 | 软件界面、数据和真实成果 |
| ComfyUI Z-Image | 本地可复现的概念图和图生图 | 软件界面、数据和真实成果 |
| api.xueai.me 视频 | 无法拍摄的短动态场景 | 软件功能、账号状态和执行结果 |
| IndexTTS2 | 本人授权的声音补丁 | 未经授权的人声 |
| Remotion | 字幕、结构、流程、数据和信息动效 | 缺失的真实过程证据 |

## 素材角色和获取责任

先给每项素材标记角色，再决定由谁获取：

- `evidence`：证明本人做过、产品确实能做、数据确实存在、过程确实发生。必须使用本人真实素材、真实网页、官方资料或可核验记录。
- `illustration`：帮助理解情绪、场景和抽象概念。可以使用公开素材、生图、生成视频和 Remotion 动效。
- `automatic`：系统能够在现有授权内自动搜索、截图、下载、生成和登记。
- `creator`：只有创作者能够提供，常见于账号后台、私域社群、客户案例、未公开项目、真实聊天记录和本人操作录屏。

能够自动获取的素材必须主动收集。需要创作者提供的素材必须进入申请队列。关键证据未到位时，对应镜头状态改为 `blocked-user-material`，不得用文字卡、假界面、生图、无关 B-roll 或未经批准的还原顶替。

只有创作者可以批准以下两种降级：

1. 修改或删除无法证明的口播结论。
2. 将镜头改成明确标记的 `流程演示` 或 `官方资料还原`。

降级处理必须记录在素材账本中，不能由制作系统默认决定。

## 画面计划

每个语义段建立一行：

```text
口播：观众听到什么
任务：观众此刻要看懂什么
输入：初始文件、页面、问题或命令
过程：点击、输入、滚动、执行、等待或状态变化
结果：页面、文件、数据、回复或前后对比
素材：来源类型和本地文件
角色：evidence / illustration
责任：automatic / creator
替代：禁止 / 需本人批准 / 允许
申请：无或 MAT-001
状态：needed / planned / sourcing / found / ready / approved / blocked-user-material
```

只有结论没有过程时，优先补录屏、屏幕操作或可核验的过程还原。不要用更多文字卡和生图掩盖素材不足。

## 素材优先级

1. 本人真实素材。
2. 实际网页和自有项目。
3. 官方或第一方资料。
4. 有明确许可证的公开素材。
5. Pexels 通用素材。
6. Codex 或 ComfyUI 生图。
7. 经成本确认的 API 视频。
8. Remotion 流程演示。

网络素材搜索必须先写清服务哪句口播。技术问题优先官方来源。搜索引擎缩略图和第三方教程截图不能直接作为产品证据。

## 素材申请

自动搜索和现有素材库检查完成后，如果仍缺少必要的创作者证据，立即使用素材申请单。一次申请只索取真正阻断当前镜头的内容，并写清：

- 对应口播和要证明的结论。
- 需要截图还是录屏，必须出现的输入、过程和结果。
- 需要遮挡的账号、姓名、头像、客户和敏感数据。
- 建议分辨率、画幅、时长、文件格式和命名。
- 缺失素材会阻断哪个镜头，是否存在需要本人批准的降级方案。

不要只说“缺素材”。给创作者一份照着拍就能完成的清单。收到文件后检查可读性、隐私、真实性和与口播的对应关系，再把状态从 `blocked-user-material` 改为 `ready` 或 `approved`。

## 网页和操作素材

- 打开真实页面后截图或录屏。
- 保存 1920 x 1080 首屏、完整页面或操作录像中的必要版本。
- 记录网址、页面区域、视口、截图日期和本地路径。
- 操作型内容优先录制点击、输入、滚动、筛选和结果变化。
- 同一段演示使用一个清晰窗口，避免多个重叠终端和无关桌面。
- 遮挡账号、邮箱、Token、客户信息、用户名和不安全权限状态。
- 账号不可用时可以使用官方资料或明确标记的流程还原，不能伪造真实登录和执行成功。

## Pexels 和网络版权

- 保存原始素材页面、创作者、主页、许可证和获取时间。
- Pexels 素材不暗示画面人物或品牌为产品背书。
- 来源不明、水印无法解释或授权范围不清的素材不能进入主片。
- 下载成功只表示文件存在，观看和登记完成后才能标记为 `ready`。

## 生图和视频生成

- 生图前写明服务的口播、观看任务、主体、构图、留白、禁止项和输出路径。
- 系列默认暖暗、米白、少量橙色、一个主要焦点，图片内部不生成可读文字。
- 生成图承担情绪和隐喻，事实由真实页面和数据证明。
- API 视频是付费异步素材。提交前确认模型、数量、时长、画幅、预计成本和用途。
- 生成完成后下载到 Day 目录，检查主体、动作、文字、手部、闪烁、接缝和首尾帧。
- Token、Key 和临时下载地址不写入 Markdown、配置、日志、截图或 Git。

## Remotion 时间线

最终口播是时间主轨。先根据语义和自然停顿划分镜头，再决定素材切点。不要让预设章节反过来绑架录音。

固定系列规则：

- 1920 x 1080，30 fps。
- 暖黑背景、米白文字、品牌橙焦点。
- 结果型开场后使用固定五秒系列片头。
- 系列固定口播位于钩子之后、正文之前。
- 正文中自然出现一次免费资料提示。
- 最后一个场景包含下期预告。

## 过程优先的动效

- 每个镜头只设置一个主要动效目的。
- 流程按照口播逐节点出现或点亮。
- 网站和终端展示输入、执行进度和结果。
- 数据在被读到时同步高亮。
- 局部推近用于阅读证据，不把整张截图慢放大当成过程。
- 入场动效通常在 0.25 到 0.6 秒内结束，然后给稳定阅读时间。
- 不让字幕、标题、卡片和背景同时持续运动。
- 连续静态信息卡不超过两个。
- 静态信息画面超过 5 秒时必须有明确阅读需要、人物表演或可见状态变化。
- 8 到 12 秒内应出现有意义的视觉推进，但不要求强行转场。

## 字幕

- 从最终口播转写，不从旧文案猜时间。
- 逐条校对人名、产品名、命令、英文、数字、空格和语病。
- 重要信息和字幕避开平台底部安全区。
- 字幕不能遮挡当前要看的输入、结果和数据来源。
- 画面需要安静阅读时，可以减少口播密度，不用字幕重复塞满一屏。

## 草稿和最终渲染

1. 先渲染片头、关键案例、复杂流程和资料提示的目标帧或短片。
2. 再渲染低成本审片草稿。
3. 建立镜头 manifest，检查每个镜头开始、中间和结束。
4. 修完已知阻断后，才渲染完整候选片。
5. 保留旧候选到 `_superseded`，不要直接覆盖唯一可用版本。
6. 最终主文件使用稳定名称，候选文件明确标记用途和授权状态。
