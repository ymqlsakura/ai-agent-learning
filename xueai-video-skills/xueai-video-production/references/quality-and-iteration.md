# 质检、迭代和发布流程

## 四层质量门禁

### 内容门禁

- 最终口播与批准文案意思一致。
- 没有错误 take、重复、漏句和未经证实的结论。
- 固定系列口播、免费资料和下期预告存在。
- 字幕与口播一致。
- 画面服务当前口播，不出现错误素材和异常数据。

### 音频门禁

分别对原始录音、处理后口播和最终成片运行 `check-video-audio` strict 模式。自动 PASS 后仍需耳机检查。

阻断项目包括削波、危险真峰值、高底噪、低信噪比、固定高频、啸叫、电源嗡声、相位和声道异常、响度不合格及明显音视频不同步。

### 视觉体验门禁

使用 `check-video-visual-experience` 观看完整成片并建立过程覆盖表。必须检查每个镜头开始、中间和结束，关键演示按正常速度观看。

阻断项目包括：

- 讲过程却只有标题、列表、截图或最终结果。
- 三个以上连续静态幻灯片镜头。
- 超过 5 秒没有合理视觉变化的信息画面。
- 关键输入、点击、执行、状态变化和结果看不清。
- 动效抢走字幕和证据焦点。
- 口播、字幕、素材和结果互相矛盾。

### 技术和合规门禁

- 项目 lint、测试、类型检查和 Remotion bundle 通过。
- 最终视频从头到尾完整解码，无意外黑帧。
- 视频、音频时长和起点在允许范围内。
- 分辨率、帧率、编码和字幕安全区正确。
- 所有本地素材存在且可读取。
- 网络、Pexels、生图、视频生成、音乐和克隆音记录完整。
- 没有隐私、Token、账号、客户信息和未授权素材。

## 技术检查示例

```powershell
npm run check
ffprobe -v error -show_format -show_streams -of json "D:\path\final.mp4"
ffmpeg -v error -i "D:\path\final.mp4" -f null -
ffmpeg -hide_banner -i "D:\path\final.mp4" -vf "blackdetect=d=0.10:pix_th=0.02" -an -f null -
Get-FileHash -Algorithm SHA256 -LiteralPath "D:\path\final.mp4"
```

根据内容选择黑帧阈值。设计上的纯黑转场不应被机械判断为错误，但必须确认不是缺素材。

## P0、P1 和 P2

### P0

事实伪造、严重隐私泄露、危险误导、错误外部操作或可能造成重大现实影响的问题。立即停止发布。

### P1

核心内容错误、关键过程缺失、错误素材、音频门禁失败、字幕严重错误、无法解码、黑帧、未授权素材或观众无法理解主线。必须修复并重渲染。

### P2

不改变核心事实，但影响节奏、可读性、动效统一、听感或专业度的问题。影响理解、声音和明显成片质量的 P2 默认关闭。纯装饰性 P2 可以由用户明确接受。

## Loop 执行约定

用户使用 `/loop N` 时，把 N 视为允许的最大迭代次数，不是跳过确认、付费授权或外部发布权限的授权。

每一轮必须：

1. 检查当前最新文件和 Git 状态。
2. 用时间码和证据分类 P0、P1、P2。
3. 修根因，不只遮盖表面现象。
4. 运行相关测试。
5. 先渲染受影响的关键帧或短片。
6. 渲染新的完整候选片。
7. 对新文件重新运行所有受影响门禁。
8. 记录新 SHA256、报告和变更。

禁止：

- 用旧文件的通过结论批准新文件。
- 只看源码或联系表就声称完整观看。
- 修改后不重新渲染全片。
- 因迭代次数快用完就降低发布标准。
- 把缺少用户授权、付费确认或真实素材误判为技术完成。

达到 P0 0、P1 0 和完成契约后提前停止循环。遇到需要用户决定的文案、付费素材、克隆授权或发布权限时，记录阻断并请求最小必要输入。

## 独立质检 Agent

独立 Agent 接收最终文件、批准文案、素材账本和必要的 Skill 路径。不要在提示中泄露期望答案。

要求 Agent 明确说明：

- 是否完整观看带声音的成片。
- 是否检查每个镜头开始、中间和结束。
- 是否按正常速度查看关键过程。
- 检查的文件路径和 SHA256。
- P0、P1、P2 数量和精确时间码。
- 是否建议发布。

独立质检提出 P0 或 P1 后，必须修复并交回同一 Agent 或另一独立 Agent 复审新文件。

## 发布条件

- P0 为 0。
- P1 为 0。
- 影响理解、听感和明显专业度的 P2 已关闭。
- 人工耳机听审完成。
- 资料承诺已经兑现。
- 发布主片没有未授权音乐和素材。
- 最终文件完整解码并记录哈希。
- 最终文件使用不可覆盖的 `dayXX-rN` 版本，并记录对应的 `xueai-motion` 版本。
- 只有用户明确授权时才执行外部发布。

## Day31 的主要教训

- 文案和录音可以正确，画面仍可能因为连续静态卡而失败。
- 联系表能发现错图和黑帧，不能证明过程和动效存在。
- 页面截图能证明结果，但不能证明操作如何发生。
- 缓慢缩放是一种构图动作，不是过程展示。
- 音频响度合格不代表没有啸叫和底噪，必须做频谱和静段检查。
- 背景音乐没有授权记录时，应从发布主片移除。
- 数据口播必须由同屏截图证明，无法证明的句子应删除或更换证据。
- 每次修复都要重新渲染和复审新文件，不复用旧结论。
