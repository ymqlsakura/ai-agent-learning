# 口播驱动的 Remotion 动效系统

## 核心判断

画面不是文案的装饰版 PPT。画面必须在正确时间帮助观众完成一个观看任务：看见结果、理解因果、跟上步骤、比较变化或核对证据。

Day31 最终版本证明了下面的组合稳定有效：语义镜头、真实素材、逐词或逐项提示、过程状态变化、克制转场和完整成片审计。未来复用的是这套判断方法，不是复制 Day31 的 17 个场景。

## 从口播到镜头

先对最终口播做带时间码转写，再按语义和停顿划分镜头。每个镜头记录：

```text
id
start / end
narration
viewerTask
input
process
result
materials
primaryMotion
cues
```

章节数量由当期内容决定。一个章节可以包含多个语义镜头，一个镜头也可以承载一组短句。不要按平均时长机械切分。

## 六种常用语义模式

### 结果接力

用于开场快速证明能力。让网站、项目、消息平台和真实成果按照口播逐个接力出现，最后停在最有说服力的结果上。

### 终端打字和执行

用于命令、Agent 或自动化。必须展示输入、执行或等待、关键结果三个状态。输出过长时只保留观众需要核对的部分。

### 流程级联

用于工作流、循环任务和多平台连接。节点按照口播依次出现，连接线在因果关系成立时再绘制，当前节点高亮，已讲节点降级，未来节点隐藏。

### 证据推近

用于网页、截图和数据。先建立页面上下文，再推近口播正在核对的区域。不能只对整张截图做慢速放大。

### 前后对比

用于优化、自动化和工作成果。保留初始状态，展示关键变化，再稳定呈现结果。对比项必须使用同一尺度和真实数据。

### 克制收束

用于免费资料和下期预告。以内容和行动为主，使用少量景深、视差或群像层次，不在结尾堆满飞入卡片。

## 口播同步规则

- 列表、命令、流程、对比和关键词使用真实口播时间码，不使用平均分配。
- 重要可见变化与对应口播尽量控制在 6 帧以内。
- 口播未提到的详细内容默认隐藏。
- 当前内容最强，已经讲过的内容保留但降低强调。
- 入场完成后留出稳定阅读窗口。
- 字幕从最终口播生成并人工校正，不从旧文案猜测。

## 动效约束

- 每个镜头只有一个主要动效目的。
- 同一场景选择一个主运动语言，辅助运动只做层次。
- 转场统一使用一个家族，默认克制的遮罩、推移或淡化。
- 所有时间动画由 Remotion 帧驱动，不能依赖 CSS animation 或随机定时器。
- 动效必须可重复渲染，随机数使用固定种子。
- 不使用难看的红色描边框作为默认强调方式。优先使用品牌橙、局部亮度、遮罩、景深、下划线或构图变化。
- 不用光标抖动、背景粒子、慢缩放或装饰闪烁冒充真实过程。

## 字幕和安全区

- 横版 1920 x 1080 默认字幕字号约 56 px，按真实成片检查，不机械固定。
- 字幕基线默认距底部约 70 px，并避开平台交互区。
- 证据、命令和字幕不能互相遮挡。
- 专有名词、命令、数字和中英文空格必须人工校正。

## 素材分期

Remotion 渲染只使用当前成片真正引用的最小素材集合。不要把整个 Day 素材库复制到 `public`，否则每次 bundle 都会复制大量无关文件。

建立 episode asset manifest，只列出本次构建需要的相对路径。使用新的空 staging 目录生成候选片，避免旧素材残留。原始素材仍保留在 Day 目录，不因分期而删除。

## 三层验证

1. 源码门禁：lint、类型检查、测试和 Remotion bundle 通过。
2. 自动动效审计：按镜头开始、中间、结束抽帧，发现近乎静止的场景。
3. 人工视觉质检：带声音看完整成片，逐镜头验证口播、过程、结果、动效和素材是否对应。

像素变化只能证明画面在变化，不能证明观众看懂了过程。最终放行必须以完整观看和过程覆盖表为准。

## 复用边界

复用：品牌色、字体、安全区、字幕、固定系列片头、转场家族、动效原语、审计工具和质量门禁。

不复用：当期章节数、具体场景结构、口播切点、素材、演示步骤和结论。每一期都重新根据文案设计。
