# XueAI 动效系统版本规则

## 目的

每次把新设计方法、组件组合或动效标准沉淀为可复用方案时，必须发布一个不可覆盖的版本。版本的作用是让用户直接看样片、看差异、看质检结果，再决定保留哪一版。

聊天结论、同名文件覆盖和只有 Git 提交都不算完成版本发布。

## 版本号

使用 `xueai-motion-vMAJOR.MINOR.PATCH`：

- `MAJOR`：整体视觉语言、镜头架构或品牌系统发生明显变化。
- `MINOR`：新增可见设计能力，或在相同输入下明显改善构图、动效和理解效率。
- `PATCH`：修正错误、兼容性或质检问题，不改变主要设计方向。

版本号只能递增，不能删除后复用。被淘汰的版本保留为 `rejected` 或 `archived`，不能从记录中抹掉。

## 每个版本必须包含

1. 版本号、日期、状态和父版本。
2. 同一冻结输入生成的完整 MP4 样片。
3. 逐秒联系表和视觉质检报告。
4. 样片 SHA256、源码提交和方法论提交。
5. 相对父版本的具体变化，不写“更高级”这类空结论。
6. 自动门禁结果和已知 P2。
7. 用户选择结果：`pending`、`selected`、`rejected` 或 `archived`。

样片、联系表和报告放进独立版本目录，文件名包含版本号。发布后禁止原地覆盖。修复后产生新版本，即使只增加 `PATCH`。

## 筛选方法

比较版本时必须冻结文案、口播、素材、时长、画幅和提示点。用户至少看到：

- 两个可直接播放的版本样片。
- 每版逐秒联系表。
- 一张只写变化和取舍的对比表。
- 构图层级、过程可见性、口播同步、品牌一致性和复用速度评分。

用户的直接观看选择优先于抽象描述。自动评分负责淘汰不合格方案，不代替审美选择。

## 发布步骤

1. 从 `design-version-registry.json` 读取当前最高版本。
2. 根据变化范围生成下一个版本号。
3. 创建新的版本目录，拒绝覆盖已有目录。
4. 两次确定性渲染并记录 SHA256。
5. 完成构建、音频、视觉、素材和提示点门禁。
6. 更新 JSON 注册表和面向用户的版本对比说明。
7. 提交 Git 后再宣布版本已经沉淀。

当前正式登记从 `xueai-motion-v2.0.0` 开始。更早方案保留在 Git 和旧样片中，但不补造缺失的正式版本数据。
