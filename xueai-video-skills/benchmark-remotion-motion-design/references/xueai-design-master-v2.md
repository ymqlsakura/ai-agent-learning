# XueAI 设计母版 V2.0.0

正式版本：`xueai-motion-v2.0.0`

状态：候选，等待与后续版本直接观看比较后确认。

版本注册表：`design-version-registry.json`。

## 定位

母版不是一套把每句话装进卡片的 PPT 主题。它是一套证据优先的编辑设计系统：真实页面承担证明，动效承担顺序和注意力，品牌视觉把不同来源的素材收拢成同一系列。

默认感受是克制、可信、温暖、精确。高级感来自层级、比例、材质和节奏，不来自粒子数量。

## 基础视觉

### 颜色

- 深色背景：`#080908`。
- 浅色纸面：`#EEE9DF`。
- 主强调橙：`#F06A2A`。
- 深色卡片：`#11120F`。
- 深色正文：`#11120F`。
- 浅色正文：`#F0ECE2`。
- 次要文字：在当前正文颜色上使用 52% 到 64% 透明度。

同一镜头只允许一个主强调色。状态成功、警告和错误确有语义时才引入第二功能色。

### 字体职责

- 大标题使用有编辑感的中文展示字体，默认回退为宋体系统栈。
- 正文和字幕使用清晰的中文无衬线字体。
- 命令、路径、数字和状态使用等宽字体。

发布母版应打包经过授权的字体文件，不能长期依赖某台电脑的系统字体。

### 布局

默认使用三种画面模式：

1. 深色证据场。真实终端、网页和操作结果占画面 52% 到 68%，文字负责解释，不盖住证据。
2. 浅色解释场。用纸面留白、步骤和前后状态讲清因果，真实素材仍保留为主视觉。
3. 全屏结果场。关键结果或人物画面占满画面，只保留一句结论和必要来源。

深色和浅色交替用于章节和认知换气，不机械地一黑一白轮播。

## 六个母版组件

### TonalCanvas

统一深色暖橙色场或浅色纸面。背景只做缓慢漂移和微弱网格，不与证据争夺注意力。

### EvidenceFrame

承载真实截图、网页和录屏。包含轻量边框、遮罩、来源标签和必要的局部聚焦。默认圆角 20 到 28 像素，禁止厚重红框。

### StateDeck

展示同一任务的前后状态，例如 `/context` 到 `/compact`、`/plan` 到 `/goal`。旧状态退到后层，新状态沿一个明确方向进入。最多同时保留两个主要平面。

### CommandPill

只在口播说到命令时出现。当前命令使用品牌橙，已讲命令降级，未来命令隐藏。不能一开始摆出完整命令墙再轮流变色。

### ProcessLoop

表达触发、检查、执行、验收和返回。节点按照口播逐个出现，当前节点高亮，真实执行截图与流程图同时存在。圆环本身不能替代真实运行证据。

### TemporalLane

表达定时和并行。时间线按口播推进，`/schedule` 和 `/workflows` 在各自词语出现前最多提前 3 帧露头。

## 动效参数

- 普通入场：8 到 18 帧。
- 主要状态切换：18 到 28 帧。
- 字幕和命令触发：允许提前 0 到 3 帧，不能明显滞后。
- 2.5D 平面旋转：通常 4 到 10 度，不做持续摇摆。
- 卡片层数：主要平面不超过 2 个，辅助层不超过 1 个。
- 一镜一个主要动作目的，入场后必须有稳定阅读窗口。
- 背景漂移速度必须低于主要内容，不能被观众首先注意到。
- 不使用 CSS keyframes 或 CSS transition 驱动导出动画，所有状态由帧决定。

## 镜头语法

每个解释型镜头按四段构建：

1. 初始状态。观众先知道从哪里开始。
2. 聚焦动作。命令、点击、输入或节点在口播时间点出现。
3. 状态推进。画面展示执行、切换、循环或比较。
4. 结果停留。给观众一个完整阅读节拍确认结果。

如果缺少第二段或第三段，先补素材，不用装饰动效填空。

## 四库使用边界

- Curvable：作为首选设计参考。可采用色场、空间层级、卡片组合和经审计的局部组件。
- RVE：作为单动作组件参考。复制前重新设计字号、比例、配色和输入参数。
- Scenes：作为动作词典。每个镜头最多引入一种来自 Scenes 的主动作。
- Playground：作为教学参考。不能进入生产依赖，不能把正弦模拟波形当成真实音频分析。

上游代码进入母版前必须保留许可证和来源说明，固定提交，并通过当前 Remotion 版本的类型检查、两次确定性渲染和视觉复核。

## 依赖策略

母版默认不直接依赖四个完整仓库。优先顺序是：

1. 使用官方 Remotion API 自己实现稳定的母版组件。
2. 从 MIT 来源复制一个经过审计的局部组件，并保留来源记录。
3. 只有组件持续独立更新且版本兼容时，才增加固定版本依赖。

新增依赖必须回答三个问题：它解决了哪个具体镜头问题，现有组件为什么不够，移除它会损失什么。

## 发布质检

- 每个动作型句子都有输入、过程和结果。
- 未来命令和节点不会提前出现。
- 证据素材可以读到关键状态，不被字幕遮挡。
- 没有连续三个静态信息页。
- 主要画面不会持续漂移。
- P0 和 P1 均为 0。
- 音频质检单独通过。
- 完整成片以正常速度观看，不以接触表代替观看。

## 参考实现

本次 30 秒参考实现位于 `motion-design-benchmark` 的 `Design-Template-05` Composition。它使用同一段 Day31 口播和同一批真实 Claude Code 素材，展示四类母版镜头：状态切换、规划到推进、循环执行、定时和并行。

任何可见设计改动必须发布为新版本，禁止覆盖 `xueai-motion-v2.0.0` 的样片和质检记录。版本生成和筛选规则见 `design-versioning.md`。
