## 核心驱动力（这些是她真正会行动的原因）
1. **帮别人解决问题**：她的启动开关在「别人需要我」上，不在「为自己」上。从小到大为别人而活——这是出厂设置，不是弱点。
2. **不想拖后腿**：需要队友和 accountability。一个人做事会觉得无所谓，但在团队里会主动变强。
3. **雪前送炭**：提前察觉别人的需求、主动帮助——这让她有巨大的成就感。
4. **AI 陪伴**：两年前就想做「能跟人正常谈恋爱、服务人类、帮助老年人的 AI 智能体」。
5. **被需要的感觉**：看到自己做的工具真的帮到某个人——那一个瞬间比什么都重要。

## 🚨 最关键的学习发现（Day 8）
**为自己做的项目她做不完。不是能力问题，是开关不在那个位置。**
帮她启动的开关必须是：看见一个真实的人 → 发现他需要什么 → 解决问题 → 被需要的感觉让一切燃料到位。

## 学习障碍
1. **最大焦虑源**：面对 VS Code 空白文件，什么都写不出来
2. **英文恐惧**：英语较差，看到英文就不知道自己在干什么
3. **知识散落**：学了就忘，知识点之间没有串联
4. **信心不足**：什么都懂一点但不精通，模糊概念很多
5. **不怕失败，怕没人需要**：路走不通她不纠结，会换一条继续走。真正的风险不是失败，是做出来的东西没人说「这个有用」

## 游戏 vs 编程（为什么游戏能坚持，编程坚持不了）
- 游戏：有队友 → 不想拖后腿 → 主动搜博主教学 → 自己总结 → 深入思考
- 编程课：没队友 → 无所谓 → 被动接收 → 学了就忘 → 没有反馈

## 正确的教法（五条法则）
1. **意义先行，代码在后**：每个项目先回答「这个工具让谁被帮助？」
2. **永不空白文件**：从已跑通的代码改起，不从零新建
3. **中文优先**：注释、变量名用中文，英文只在必须时出现
4. **30 行，30 分钟**：第一个版本不超过 30 行，30 分钟跑通——快速拿到反馈
5. **队友在看着**：每次会话结束写总结，可分享给在乎的人
