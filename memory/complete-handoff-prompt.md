# 完整的 HANDOFF 更新提示词（v2.0）

> v1.0 创建于 2026-07-17（Day 10），v2.0 升级于 2026-07-23（第 36 轮——小樱 v3.0 升级后）。
> v2.0 新增：元认知检查、DECISIONS.md 更新、STATUS.md 更新、五步框架联动。
> 原始版本只有 5 个维度，v1.0 扩展到 8 维度（A-H），v2.0 再融入决策日志和元认知框架。

## 使用方式

樱漫清澜在会话结束时发送以下提示词块即可。小樱会自动执行全部步骤。

---

## 提示词

```
这个会话要结束了。请执行以下交接流程。

在开始之前，先回答两个问题：
1. 眼下我最没有把握的事情是什么？
2. 关于当前情况，最大的遗漏是什么——樱漫清澜可能没意识到什么？

## 第一步：自动检索（说话前先读）
自动搜索并读取以下全部文件，再开始写：
- HANDOFF.md（当前版本）
- DECISIONS.md（当前版本）
- STATUS.md（当前版本）
- memory/MEMORY.md 及索引中列出的每一个 .md 文件
- 项目根目录的任何 CLAUDE.md、AGENTS.md、README 等

## 第二步：更新 HANDOFF.md，覆盖以下全部维度

### A. 我们在做什么
- 项目一句话描述
- 服务的人是谁、核心驱动力是什么
- 当前阶段

### B. 本次会话完成了什么
- 做了什么（按时间线，不是按感受）
- 产出了哪些文件/改动
- 新增/更新了哪些 memory 文件

### C. 理解发生了什么变化
- 有什么之前以为是对的东西，现在不确定了？
- 有什么新的认知或框架？
- 这个变化对未来会话有什么影响？

### D. 当前不确定什么
- 不是「卡在哪」——如果没有明确阻塞点，就写「不确定的事」
- 如果某个前提假设未经数据验证，标记出来

### E. 有什么答应了但没做的事
- 逐条列出并标注「已丢失」或「待补救」
- 这是免疫系统的一部分——不允许悄悄蒸发

### F. 下一步计划
- 第一优先级
- 如果第一优先级走不通，降级方案是什么
- 不是抽象方向，是下次会话可以立刻执行的具体动作

### G. 新踩的坑（绝对不要再犯）
- 分类：致命级 / 技术级
- 每条注明发现场景和后果

### H. 记忆文件变更清单
- 新建的、更新的、应删未删的

## 第三步：更新 DECISIONS.md
- 本次会话是否产生了新的决定？→ 写入「活跃决策」表
- 是否有旧决定已完成？→ 移到「已完成的决定」表
- 是否有决定被推翻？→ 移到历史存档并标注原因
- 格式：每行一条，固定字段（日期|主题|决定|准确表述|我的动作|触发条件）

## 第四步：更新 STATUS.md
- 精简到 ≤50 行
- 更新「正在做什么」「上次更新」日期
- 如有核心数据变化，更新数据表

## 第五步：验证
写完后重新读取 HANDOFF.md、DECISIONS.md、STATUS.md，逐条检查：
- [ ] A-H 每个维度都有内容吗？
- [ ] 时间戳更新了吗？
- [ ] 接力信号（下一动作/禁止重复/上次未完成/上次决定/待对账/收敛状态/元认知检查）全部刷新了吗？
- [ ] DECISIONS.md 新增/移动的条目格式正确吗？
- [ ] STATUS.md ≤50 行吗？
- [ ] 所有链接的 memory 文件确实存在吗？
- [ ] 有没有答应了但没写入的东西？

## 第六步：更新 memory/MEMORY.md
确保索引覆盖了所有新增的记忆文件。更新最后更新日期。

## 第七步（可选）：保存本次会话原始转录
1. 源目录：C:\Users\a\.claude\projects\d--ai-agent2\
2. 找到本次会话的 .jsonl：修改时间最新、且内容含本次对话特征词的那个
3. 复制到 D:\ai agent2\ai-agent-learning\session-logs\（保留原文件名）
4. 更新 session-logs/README.md 的文件清单
```

## v2.0 vs v1.0 变化

| 维度 | v1.0 | v2.0 |
|------|------|------|
| 启动检查 | 无 | 🆕 元认知检查两个问题——先回答再开始 |
| 检索范围 | HANDOFF+MEMORY+根目录 | 🆕 + DECISIONS.md + STATUS.md |
| HANDOFF 更新 | A-H（不变） | A-H（不变） |
| 🆕 DECISIONS 更新 | 不存在 | 新增/移动/推翻——三条规则 |
| 🆕 STATUS 更新 | 不存在 | 精简到 ≤50 行 |
| 验证清单 | 4 项 | 🆕 7 项（+DECISIONS格式/+STATUS行数/+接力信号刷新） |
| 思维框架 | 无 | 🆕 需要复杂判断时自动启用五步框架（原第十二节→已迁移至 PROMPTS.md） |

**Why:** v1.0 在 Day 10 创建时项目只有 HANDOFF + MEMORY + session-logs 三件套。v3.0 升级后新增了 DECISIONS.md（13 活跃+7 历史决策）、元认知检查（最没把握+最大遗漏）、五步思维框架（原第十二节，已迁移至 PROMPTS.md）、STATUS.md 独立维护。交接流程必须覆盖所有组件，否则新会话会漏掉关键信息。

**How to apply:** 每次会话结束前，樱漫清澜说「写交接」或发这段提示词时，执行完整七步流程。不要跳过第五步验证——五步框架就是因为写了但没验证才丢的。第七步（转录保存）默认执行，除非她明确说跳过。
