# 学习路线：真实需求驱动

> 旧路线（五项目珠链）已废弃。底层逻辑错误：为自己做的项目樱漫清澜做不完。
> 新路线：永远从一个真实的人的真实需求出发。

## 当前阶段：聊天记录分析器

**工具**：`stage-5-document-assistant/chat_analyzer.py`
**技能**：读文件 → 调 DeepSeek API → 输出分析报告 + HTML 页面
**已完成**：真实聊天记录（和姜姜）跑通，Level 1 无报错 ✅、Level 2「确实挺准的」✅（Day 9）
**下一步**：行为检验（HANDOFF 第六节的事前预测 P1-P3）；长聊天分片处理（超过 2000 token 会截断）

## 核心模式

所有项目遵循同一个技术内核：
```
读文件 → 调 DeepSeek API → 输出结果
```

这是 doc_assistant.py 的模式，也是 chat_analyzer.py 的模式，也是未来所有工具的模式。
变的只是「读什么」和「输出什么」——技术不变，服务对象变。

## 三条路径（按需探索）

### 路径 A：聊天分析 → 深入/扩散（当前主路径）
先看清**她自己想看懂的**关系（Day 9 已验证能驱动她完整做完）→ 若她愿意，再帮别人分析 → 扩散
技能积累：prompt 优化 → 不同聊天格式适配 → 分片处理长对话 → 分析维度扩展
（叙事基于 Day 10「看清楚」工作假设；但「分析想看懂的关系能驱动她」是已发生的行为事实，不依赖假设成立）

### 路径 B：文档总结 → 变现
doc_assistant.py 已是能用的工具 → 挂闲鱼 ¥25-30/次
技能积累：客户沟通 → 需求理解 → 交付标准

### 路径 C：新需求 → 新工具
发现某个真实的人有具体的、重复的、让人烦的小任务 → 3 天内做出来
技能积累：按需学习，学到就用

## 知识串联

所有路径共用同一个技能栈（已掌握）：
- `open("r"/"w"/"a")` — 文件读写（Stage 5）
- DeepSeek API 调用（Stage 1）
- `def` 函数定义（Stage 4）
- `if/else` 条件判断（Stage 3）
- `while True` 循环（Stage 2）
- import 模块（Stage 5）

不需要学新东西才能做下一个工具——已有的技能已经够了。差的只是一个真实的人说「我需要」。
