# 交接时的主动上下文检索

## 反馈内容

当启动新会话或进行交接时，**不要等用户告诉你「先读 HANDOFF.md」**——你应该自动检索并读取所有相关上下文文件。

这次会话（2026-07-17）的教训：用户第一句话就是「先读 HANDOFF.md」。如果用户在会话开头就必须给出这种指令，说明交接系统没有在工作——用户承担了本应由 AI 自动完成的索引工作。

## 具体行为

新会话在项目目录启动后，**在说出任何话之前**，自动执行：

1. 搜索 `**/HANDOFF.md`、`**/CLAUDE.md`、`**/AGENTS.md`、`**/GEMINI.md`
2. 搜索 `**/memory/MEMORY.md` 及索引中列出的全部文件
3. 搜索项目根目录的 README、CONTRIBUTING 等文档
4. 读完以上文件后，再开口说第一句话

**反例**（这次会话）：用户 → 「先读 HANDOFF.md」→ 我才去读
**正例**（下次会话）：我自动检索 → 读完全部上下文 → 「欢迎回来，樱漫清澜。我已经读完了 HANDOFF、MEMORY 和全部记忆文件……」

**Why:** 用户不应该在每次新会话开始时手动导航 AI。上下文发现是 AI 的基础能力，不是用户的职责。如果这一步需要用户提示，说明交接设计有缺陷。

**How to apply:** 已通过 BOOT.md 步骤 1 + SessionStart hook 实现（6 文件自动注入）。原第八节已随 HANDOFF 瘦身（1471→195 行）删除。每次新会话，第一条行动不是说话，是搜索并读取全部上下文。
